# 包体优化与抖音分包方案（2026-11-25）

## 一、这轮做了什么（已提交）

| 优化 | 前 | 后 | 说明 |
|---|---|---|---|
| 删除未引用原始图集 | 28.7 MB | — | `assets/char/raw_0~2.png` 三张 5.6 MB、`assets/spine4/` 1.1 MB，代码里完全没引用（旧 4.x 路线遗留） |
| 美术 PNG → WebP | art 内 31 张、spine 内 45 张 | — | `art` 走代码里的 webp 优先加载（失败回退 png），`spine` 图集页码同步改写为 `.webp` |

| 音频重编码 | 96 kbps 单声道 6.4 MB | 56 kbps 单声道 2.97 MB | 81 首全部处理 |
| 删废弃引擎包与死代码 | — | −2.0 MB | `vendor/phaser.min.js` / `pixi.min.js` / `pixi-spine.js` 从未被引用；`src/battle_old.js` 同 |
| 抖音分包清单 + 构建脚本 | — | 见下 | `tools/minigame_manifest.py`、`tools/build_minigame.py` |

**资源总量：28.7 MB → 18.15 MB（−37%）**。H5 首屏 168 个请求、约 3.3 MB。

## 二、分包结果（`python3 tools/minigame_manifest.py`）

| 包 | 文件数 | 体积 | 内容 |
|---|---|---|---|
| main | 215 | **3.99 MB**（构建后 3.54 MB） | 入口、脚本、数据表、vendor、被使用的 UI/图标 art、小怪立绘 |
| pkg_bg | 1 | 0.11 MB | 超大背景图（>100 KB） |
| pkg_battle | 136 | 2.86 MB | 全部 Spine 骨架（进战斗前按需拉） |
| pkg_audio | 81 | 2.97 MB | 全部音效 |
| 合计 | 433 | 9.93 MB | 满足整包 20 MB；主包 ≤4 MB |

另有 **600 个原包遗留美术（8.22 MB）不进任何包**：多为 Unity TMP 字体图集（如 1.19 MB 的 `NotoSansSC-Medium CH Atlas`）和原工程残留贴图。判定方式 = 「playwright 走过全部界面真实请求过的 art（167 个）」∪「`data/*.json` 里出现过的贴图路径」。

## 三、构建用法

```bash
python3 tools/minigame_manifest.py   # 重新统计 -> minigame/package_manifest.json
python3 tools/build_minigame.py      # -> build/minigame/（含 game.json、project.config.json）
```

`build_minigame.py` 把 `data/*.json` 压成单行（省约 45%），分包内保留原始相对路径（`subpackages/pkg_battle/assets/spine/xxx`），方便运行时做前缀重映射。


## 三·五、抖音适配层（本轮新增）

- `src/tt.js` 增加分包解析：`pkgOf / assetPath / ensureAsset / loadAllPkgs`；H5 没有 `PKG_MAP` 时原样返回，行为零变化。
- `core.js` 的 `loadImage` / `loadSpine` 与 `main.js` 的 `loadAudio` 改成「先 `ensureAsset` 确保分包下载 → 再用 `assetPath` 取真实路径」，骨架贴图页真正 await，避免分包没下完就设 src。
- 新增 `minigame/adapter.js`：浏览器 API → 小游戏 API（`document` 壳、`Image → tt.createImage`、`fetch → FileSystemManager.readFile / tt.request`、`rAF → setTimeout`）。
- `tools/build_minigame.py` 把 adapter + `PKG_MAP` + 全部业务脚本拼成 `build/minigame/game.js`（488 KB，`node --check` 通过），并跳过 src/vendor/index 的重复拷贝。
- `main.js` 的 `fit()` 在抖音下用 `TT.info()` 的 screenWidth/Height 兜底，避免 `window.innerWidth` 为 undefined。

踩到的两个坑：`assetPath` 被当成裸函数传参丢了 `this`（`this.pkgOf is not a function`），17 个骨架全部加载失败、敌人池为 0；改成箭头函数包装后恢复。另一处是 `?auto=1` 自动开局没 await `startBattle`，会用空敌人池 reset，已补。

**仍未在抖音开发者工具里跑过**：canvas 尺寸缩放、触摸事件、`tt.createImage` 对包内路径的兼容、分包加载时序都还没实机验证。

## 四、还没做的（抖音真机前的硬骨头）

1. **路径重映射层**：分包加载后资源位于 `subpackages/<pkg>/assets/...`，需要在 `loadImage` / `loadSpine` / 音效路径前加当前已加载包的前缀，并等 `tt.loadSubpackage` 完成再请求。
2. **入口改写**：抖音小游戏无 DOM，`index.html` + `document`/`canvas` 要换成 `game.js` + `tt.createCanvas`，`Image`→`tt.createImage`，`fetch`→`tt.request`。工作量最大。
3. **真实广告位 ID**：`src/tt.js` 的 `adUnitId` 仍是占位。
4. **art_usage.txt 刷新**：新增界面/资源后需重跑 playwright 采样，否则新资源会被误判为遗留。
